# i18n — Type-Safe Translations

YAML catalogs compiled into typed Kotlin accessors, with a build-time checker that catches missing
keys, missing languages and placeholder mismatches before they reach production.

- Package: `io.peekandpoke.ultra:i18n`
- Version: {{ultraVersion}}
- Platforms: JVM, JS
- Docs: https://peekandpoke.io/ultra/i18n/

## Quick Start

```kotlin
import io.peekandpoke.ultra.i18n.I18n
import io.peekandpoke.ultra.i18n.Locale
import io.peekandpoke.ultra.i18n.MapI18nCatalog

val catalog = MapI18nCatalog(
    "en" to mapOf(
        "checkout.greeting" to "Hello {{name}}!",
        "checkout.items_one" to "{{count}} item",
        "checkout.items_other" to "{{count}} items",
    ),
    "de" to mapOf(
        "checkout.greeting" to "Hallo {{name}}!",
    ),
)

val i18n = I18n(locale = Locale("de"), fallback = Locale("en")) {
    install(catalog)
}

i18n.resolve("checkout.greeting", mapOf("name" to "Alice"))  // "Hallo Alice!"
i18n.resolvePlural("checkout.items", count = 3)              // "3 items" (falls through to en)
```

## Core Types

| Type            | Purpose                                                                       |
|-----------------|-------------------------------------------------------------------------------|
| `I18n`          | Immutable state: locale, fallback, installed catalogs. `withLocale()` returns a new instance |
| `Locale`        | Language + optional region, BCP-47 shape. Normalized at construction           |
| `I18nCatalog`   | A source of templates keyed by fully-qualified key + locale                    |
| `MapI18nCatalog`| In-memory catalog for tests and hand-written cases                             |
| `MessageResolver`| Walks the locale chain and catalog precedence; single-pass substitution       |
| `I18nTranslate` | Open surface — module namespaces hang off it as extension properties           |
| `I18nFormat`    | Closed surface for dates/numbers/currency (seam only; CLDR not implemented)    |

## Locale

```kotlin
Locale("de")                 // de
Locale("de", "CH")           // de-CH
Locale.parse("de_ch")        // de-CH — separator and casing normalized
Locale.parse("DE")           // de

Locale.parse("de-CH").base   // de   — language without region
Locale("de").base            // de   — a base locale returns itself
Locale.parse("de-CH").tag    // "de-CH"
```

Always run untrusted tags (e.g. a language stored on a user record) through `Locale.parse`.

**Limitation:** only language + region are modelled. The second subtag is always treated as a region
and upper-cased, so script/variant tags such as `zh-Hant` are mis-parsed as `zh-HANT`.

## Resolution — two axes

The locale chain is the OUTER loop; catalog precedence is the INNER one. First hit wins.

```
chain:     locale -> locale.base -> fallback -> fallback.base   (de-CH, de, en)
catalogs:  highest precedence first (app before framework)
```

A more specific locale always beats a less specific one; within the same locale the app beats the
framework.

**The fallback is required and must NOT be derived from the locale.** It has to be a concrete target
language known to be complete — deriving it from `locale.base` leaves `de-CH` falling back to `de`
and then to nothing.

**A missing key returns the key itself** rather than throwing or rendering empty.

## Placeholders

Placeholders are `{{name}}`. Substitution is **single-pass**: a substituted value is never re-scanned,
so a value containing `{{...}}` can never be re-interpreted as another placeholder.

```kotlin
i18n.resolve("greeting", mapOf("name" to "{{secret}}", "secret" to "hunter2"))
// -> "Hello {{secret}}!"   NOT "Hello hunter2!"
```

Unknown placeholders are left in place rather than blanked.

## Plurals

Separate keys with `_one` / `_other` suffixes. `resolvePlural` selects the form and supplies `{{count}}`.

```kotlin
i18n.resolvePlural("checkout.items", count = 1)   // "1 item"
i18n.resolvePlural("checkout.items", count = 7)   // "7 items"
```

Falls back `_one` -> `_other` -> base key. Selection currently uses the simple `count == 1` rule, not
CLDR plural categories.

## Catalogs & Codegen (Gradle plugin)

YAML lives at `src/<sourceSet>/i18n/messages.<locale>.yaml`.

```yaml
checkout:
  greeting: "Hello {{name}}!"
  is: "reserved words are fine"
  greet-user: "Hi {{first-name}}"
  items_one: "{{count}} item"
  items_other: "{{count}} items"
  nested:
    deep: "Deep {{value}}"
```

```kotlin
apply<I18nPlugin>()

configure<I18nExtension> {
    packageName.set("com.example.app.i18n")
    moduleName.set("App")        // prefix for generated names; defaults to project name
    fallbackLang.set("en")       // defines the generated API surface
    requiredLangs("de")          // must be at full key parity with the fallback
    // sourceSet.set("main")     // for a plain kotlin("jvm") module; default commonMain
}
```

Generated code lands in `build/generated/i18n/<sourceSet>/kotlin` and is registered on the source set
via the task provider, so every compilation depends on generation automatically.

Generated usage:

```kotlin
val I18nTranslate.checkout: CheckoutI18n get() = CheckoutI18n(i18n)

i18n.translate.checkout.greeting(name = "Alice")
i18n.translate.checkout.items(count = 3)
i18n.translate.checkout.nested.deep(value = "x")
```

**The fallback catalog alone defines the API.** Other languages may omit keys (they fall through the
chain) but can never add one the fallback lacks.

## The checker (`checkI18n`, wired into `check`)

| Finding                                                     | Severity                              |
|-------------------------------------------------------------|---------------------------------------|
| A `requiredLangs` language is missing a key, or absent       | Error — fails the build               |
| A locale defines a key the fallback does not have            | Error — fails the build               |
| A locale's placeholders do not match the fallback's          | Error — fails the build               |
| An optional language is incomplete                           | Warning — error under `-Pi18n.strict` |

Report written to `build/reports/i18n/check.txt`. `requiredLangs` accepts base languages only — a
regional variant is rejected, since a region inherits from its base.

## Catalog precedence

Each module ships its own catalog; later installs win on shared keys.

```kotlin
val i18n = I18n(locale, fallback) {
    install(KraftFormsI18nCatalog)   // framework first
    install(AppI18nCatalog)          // app last — overrides on conflict
}
```

## Kraft integration

```kotlin
val kraft = kraftApp {
    semanticUI()
    i18n(
        I18nController.create(locale = Locale("en"), fallback = Locale("en")) {
            install(AppI18nCatalog)
        }
    )
}
```

`I18nController` is a `Stream<I18n>`. `create` persists the chosen language in localStorage (default
key `kraft.i18n.lang`); boot precedence is stored value -> `initialLang` -> browser language. Use
`I18nController.inMemory(...)` for tests. Kraft's form catalog is ALWAYS installed first at lowest
precedence, so validation messages translate even if the app provides nothing.

In a component:

```kotlin
class GreetingComponent(ctx: Ctx<Props>) : Component<Props>(ctx) {
    private val t by Translations

    override fun VDom.render() {
        h1 { +t.checkout.greeting(name = props.name) }
    }
}
```

`by Translations` subscribes to the translation stream, re-renders on language change, and
unsubscribes on unmount. There is a matching `by Formatting`. With no controller registered it
degrades to returning the key rather than crashing.

Switch language with `i18nController.setLang("de")`.

Form validation rules resolve their messages through the same surface, so errors follow the selected
language with no extra wiring. Rules may be suspending; the form controller exposes a status and a
submit guard for in-flight async validation.

## Known limitations

- Script/variant subtags (`zh-Hant`) are not modelled — the second subtag is always a region.
- Plural selection is `count == 1`, not CLDR categories.
- `i18n.format` is a seam exposing the locale; CLDR-backed date/number/currency formatting is not
  implemented yet. Route formatting through it anyway so call sites do not move later.
