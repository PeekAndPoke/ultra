## What shipped

- `B2bUser` (`@Vault`, implements `HasOrgMemberships`) + `B2bUsersRepo` (`b2b_users`, unique email,
  `findByEmail`) + `B2bUserModel` (common, `USER_TYPE = "B2bUser"`).
- `B2bRealm`: `OrgPolicy.Required`, overrides `getAccessibleOrgs` / `resolveSelectedOrg` over
  `OrgsStorage`, and `generateJwt` encodes the session via `buildOrgPermissions(memberships, selected)`.
  The generic 0/1/n flow lives in `AuthRealm.issueSignIn` — the realm only supplies hooks.
- Fixtures seed orgs (`acme`, `globex` via `ensureBySlug`) + three b2b users covering the cases:
  `noorg@b2b.test` (0), `single@b2b.test` (1), `multi@b2b.test` (2). Password `S3cret123!`.
- Wiring: `module(B2bModule)`; CORS triplets for `36591` (b2b) and `36592` (b2b2c) in `server.kt`;
  `baseUrls.b2b` / `.b2b2c` in dev + test conf.

## Org-selection flow — validated

`B2bAuthFlowTest` (anonymous sign-in, no token needed) asserts 0 → denied, 1 → `Success`
(auto-select), n → `OrgSelectionRequired` with the right choices. **The org logic is correct**: on
every run the two non-flaking cases pass and the failing one is always the password check, never an
org assertion.

## Blocker (needs coordination with the security agent)

The test flakes on `com.password4j.BadParametersException: "Invalid hashed value"` — a stored password
hash is intermittently corrupted at **write time** under concurrent fixture install (a *different*
sign-in fails each run). This is the pre-existing shared-DB/hasher-concurrency flake (see
`20260718-o3-org-signin.md`, `20260720-auth-error-account-enumeration.md`) and sits in the security
agent's active vault/auth-concurrency domain (`20260720-vault-hook-reentrancy.md`, the
`VaultHookScope` work, the kontainer singleton-trap). Not committing a red-most-runs test until the
flake is resolved — the flow test is written and held.
