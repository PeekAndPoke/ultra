# 0.119.0

A release with many breaking changes, nearly all in Kontainer and datetime. Kontainer validates every injection form
and refuses more blueprints at the first `create`. In datetime a time slot is a start and a duration, so overnight
and multi-day slots exist; 24:00 is a value; a zoned date-time keeps its instant. Stored slots and 24:00 have new
values: update readers before writers.

## Before you update

**Kontainer**

- **`InjectionType` and `ServiceProvider.Type` are gone** (ULTRA-00319): a service has a `ServiceType` (`Singleton`,
  `Prototype`), a `ServiceKind` (`Static`, `Dynamic`, `SemiDynamic`) and an `overridden` flag. The changelog lists
  each old name with its replacement.
- **Redefining a service** (ULTRA-00331): the first definition fixes singleton or prototype; if either definition is
  dynamic, the service is dynamic.
- **`extend` applies the same rule against the base** (ULTRA-00330): eight of the 16 combinations change.
- **`Kontainer`, `InjectionContext` and `KontainerBlueprint` cannot be registered** (ULTRA-00336), and they **cannot be
  overridden** at `create` or `clone` (ULTRA-00336).
- **`clone { with { } }` runs the checks of `create`** (ULTRA-00332): `KontainerInconsistent` where it threw
  `ServiceNotFound`; no override lambda runs before a refusal.
- **Every `create` of an invalid blueprint fails** (ULTRA-00327), not only the first.
- **A dependency cycle through `List<T>` is a validation error** (ULTRA-00328), which can stop an app at boot. Most
  likely hit: a service in its own list, `CompositeHandler(all: List<Handler>) : Handler`; register it under a type
  outside the list.
- **An ambiguous single-service injection is reported as ambiguous**, also where it was reported as a cycle
  (ULTRA-00334).
- **An ambiguous nullable injection (`T?`, `Lazy<T?>`) is a validation error** (ULTRA-00335); it injected null.
- **`ServiceProviderFactory`'s constructor and `dynamics` are internal** (ULTRA-00346): kontainers come from `create`
  and `clone` only.
- **An override whose class is itself a registered dynamic replaces exactly that service** (ULTRA-00345); it was
  `ServiceAmbiguous`.

**Datetime: time slots**

- **`MpLocalTimeSlot` is a start and a duration** (ULTRA-00341): create it with `MpLocalTimeSlot.of(from, duration)`
  or `of(from, to)`; the constructor and `copy` are gone. `to` is derived. A slot is always finite: longer lengths,
  `Duration.INFINITE` included, are cut to `MAX_DURATION_MILLIS` (ULTRA-00343).
- **Overnight and multi-day slots** (ULTRA-00341): `to` before `from` is overnight, not invalid; `of(10:00, 25.hours)`
  is 25 hours; `Partial.asValidRange()` with the end before the start is an overnight slot; `component2()` is the
  duration; the predicates work across midnight on the 24-hour clock.
- **`date.toRange(slot, zone)`** (ULTRA-00341, ULTRA-00343): ends by the clock, a skipped hour moves to the first
  existing time, always two-ended; a start the platform cannot represent throws.
- **Stored shape `{from, duration, to}`** (ULTRA-00341): the old `{from, to}` still reads; an older reader does not
  understand the new one. Update readers before writers.
- **`splitWithGaps`**: no modulo 24 h for steps and gaps (ULTRA-00215); no `maxSlots`, never throws, a lazy read-only
  view of at most `Int.MAX_VALUE` parts (ULTRA-00341). Check `size` before `map` on user input.
- **`completeDay` ends at 24:00** (ULTRA-00341): stored as `86400000`; an older reader sees "never open".
- **A slot of exactly 24:00 ends at `EndOfDay`** (ULTRA-00341), and so does `fromHourToHour(_, 24)` (ULTRA-00341).

**Datetime: 24:00**

- **`MpLocalTime.EndOfDay` is a value** (ULTRA-00341): `hour` can be 24; a client sending `86400000` gets 24:00, not
  00:00.
- **`parse` refuses "24:00:01" and "24:30"** (ULTRA-00341).
- **24:00 is stored as `86400000`** (ULTRA-00341): an older reader reads it as 00:00. Update readers before writers.

**Datetime: zoned values, months, ranges**

- **`MpZonedDateTime` keeps its instant** (ULTRA-00211): both sides of a DST overlap are distinct values.
- **Its equality compares instant and zone** (ULTRA-00211); use `isSameInstant` to compare points in time.
- **`compareTo` orders by instant, then local time, then zone** (ULTRA-00211).
- **A time in a DST gap reads back as the resolved time** (ULTRA-00211).
- **`toString()` shows the offset** (ULTRA-00211); `toIsoString()` and the stored format are unchanged.
- **`.jvm` and `.mp` are exact over the whole range** (ULTRA-00211, JVM).
- **`atStartOfDay()`, `atStartOfMonth()`, `atStartOfYear()` start at the end of a gap at midnight** (ULTRA-00211).
- **The constructor `MpZonedDateTime(datetime, timezone)`, `copy` and destructuring are gone** (ULTRA-00211): use
  `MpZonedDateTime.of(datetime, timezone)`.
- **`month` and `dayOfWeek` return `MpMonth` and `MpDayOfWeek`** (ULTRA-00210); a comparison with a kotlinx entry
  through an untyped API (`equals`, `shouldBe`) is now false. `offsetAt(MpInstant)` is gone: use `offsetSecondsAt`
  (ULTRA-00210).
- **A zone id not shaped like an IANA region id is refused** (ULTRA-00317), also on native, with a bounded message.
- **`asListOfDates()` returns a lazy read-only view** (ULTRA-00341): a cast to `MutableList` fails.

**Mutator**

- **A write through a held element mutator is dropped when its row is gone or holds another instance**
  (ULTRA-00234), for example after a sort or a drag-and-drop move.
- **The `ListMutator` list iterator throws the standard exceptions** (ULTRA-00234).

**Cache**

- **ultra:cache no longer depends on ultra:datetime** (ULTRA-00159): declare it yourself if you used it through cache.
- **TTLs run on a monotonic clock** (ULTRA-00159).
- **TTLs never throw; zero or negative means "do not keep"** (ULTRA-00159).
- **A zero refresh TTL no longer reloads every key on every pass** (ULTRA-00159).
- **A loop delay of zero or less runs as 1 ms** (ULTRA-00159).
- **`maxEntries` and `maxMemoryUsage` are soft bounds** (ULTRA-00159).
- **`NullableCache.getOrPutAsync`**: a put during it wins, a self-cycle fails instead of hanging, cancellation is
  respected (ULTRA-00159).

**Funktor**

- **`KontainerCollector.Data.Service.type` is a `String`** (ULTRA-00319); the wire names are unchanged.

## New

- **Kontainer:** `dynamicPrototype()`, a new instance per injection, bound to the kontainer (ULTRA-00319).
- **Datetime:** `MpLocalTime.EndOfDay` (ULTRA-00341); `isSameInstant` (ULTRA-00211); `MpLocalTimeSlotRawData` and its
  serializer (ULTRA-00341).
- **Common:** `ComputedList`, a read-only list that computes each element on demand (ULTRA-00341).
- **Codegen:** `MpLocalTimeSlot` in the TypeScript runtime (ULTRA-00341).

## Fixed

- **Kraft addons:** the three.js component gives up its WebGL context when it unmounts (ULTRA-00348); the pdf.js
  viewers end their worker (ULTRA-00349); the signature pad and the old select field remove their listeners
  (ULTRA-00350).
- **Logging:** the database log stores stack traces again (ULTRA-00158).
- **Datetime:** `splitWithGaps` and `atStartOfPrevious` no longer loop forever; `numDaysInMonth` comes from the
  calendar; the zone caches on JS and native hold supported ids only.
- **Mutator:** `subList()` and `slice` work; element mutators write to their own row.
- **Kontainer:** the dynamics check no longer keeps override lambdas alive (ULTRA-00337).
- **Cache:** a dozen fixes to expiry, refresh, size bounds and failure handling.

Smaller fixes: see the changelog.
