Recommend (a). Then either do Step 5 (M) or park it. Recommend: decide (a) now, park Step 5 as its own ticket in the saas epic, close 00110 as DONE for the auth-side ids. Dep: none on auth tickets, but it touches funktor/saas models.
3. **D3 Pepper (00064).** Build it, or park? Value is DB-only-leak defence; cost is a stored-hash-format change (key id) and secret-management burden, and with Argon2id + rehash-on-login already in, marginal. Recommend PARK to future (no app is live; revisit before a hosted offering), keep the design in the ticket. If wanted: do after 00065.
4. **D4 Password policy (00065).** (a) change default to length-first (>=12) now? (b) add HIBP breach check? Recommend (a) yes, (b) yes but as an injectable, default-off-in-tests check, as ONE ticket; no app is live, so the default can change freely. Also refresh the stale line refs in the ticket.
5. **D5 Frontend base URL single-sourcing (00068 Part 2).** Options: convention only (document) / realm model carries canonical base plus dev-time origin assertion / shared `RealmFrontend` descriptor. Recommend: document the convention now (S), park the model field; close 00068 as DONE-for-Part-1 with Part 2 split into a small ticket only if wanted.
6. **D6 Sign-up mail abuse (00128).** Which of A (OnBeforeSend hook + cooldown, per-JVM state), B (per-flow cooldown, does not fix aliasing), C (fold +tags in EmailAddress, changes identity semantics), D (captcha/capability)? Recommend A, in-process, with the mail sent off the request path (also fixes the timing tell); add enumeration fix (same answer for active address + notice mail) in the same ticket; reject C. Security-critical, so red team and mutation checks apply. L.
7. **D7 Session revocation (00136).** The five questions stand as the ticket records them, with its recommendations: (1) default `Vault`, revocation on; (2) no device list, drop device meaning of `deviceFingerprint`; (3) no session reuse, one row per sign-in; (4) self-service revoke only; (5) row `expiresAt` = absolute lifetime (`sessionLifetime`, 30 d), refresh refuses a gone/expired row and never extends it. Already decided: sessions stored hashed. One more the ticket does not ask: what happens to tokens without `funktor:sid` after upgrade (recommend: refuse them, force re-login; nothing is live). Recommend: accept all five plus that one; it is the highest-value item (blocks 00188 value, closes the refresh-launders-forged-token gap).
8. **D8 JWT hardening (00178).** Require `exp` (recommend yes) and a boot WARN for keys older than 180 days (recommend yes). Both S, together one small ticket; then close 00178.
9. **D9 CSP / Trusted Types / TTL (00188).** Recommend splitting: TTL is demo config, do after 00136 (S); CSP + Trusted Types is a large cross-app effort, PARK as its own epic item or move to a Kraft/frontend epic (it is not "auth and sessions"). Close 00188 out of this epic.
10. **D10 Close 00030 as superseded** (see table), carving email change out as a new ticket and parking demo pages. Needs the maintainer's OK because it drops planned scope (new-device mail, userapp pages, session-management UI).
