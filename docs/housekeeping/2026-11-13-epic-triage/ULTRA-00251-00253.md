## Decisions

1. **00098 composable module builder.** Question: build the self-validating `funktor { core(); rest{}; saas{} }` DSL now? Options: (a) full builder (L, breaking), (b) only the two boot checks it names (saas needs a backend; `Stored<T>` param needs a repository) as `RouteBootCheck`/app-start hooks (S-M), (c) park. Recommendation: (b), then close 00098 as "narrowed" and leave the builder for the v1 roadmap (ULTRA-00028).
2. **00102 request ids.** Question: do it before closing the epic? Options: build, or park as an idea ticket outside the epic. Recommendation: park (move to a future/idea state); it needs an MDC-like decision in `ultra/log` first.
3. **00124 item 2 secret redaction.** Question: add explicit `redacting(secret)` or leave link-only anonymization with clearer KDoc? Recommendation: do the KDoc rename now (S) and open a ticket for `redacting(..)` only when the activation code feature stores a non-URL secret.
4. **00124 item 4 sender default.** Question: config-sourced default `Email.source` in messaging, or just fix the demo realms? Recommendation: demo-only fix (read the address from demo config); no framework API.
5. **00164 F4 ordering.** Question: should `listItems(path, limit)` mean "first N by name" or "newest N"? Recommendation: sorted by name, drop "newest" from both KDocs (timestamp-named insights files sort correctly).
6. **00190 request-history link.** Question: return the insights record id in the response so the Kraft request history can link, or keep no link? Recommendation: keep no link, delete the stale comment reference and close; the record is written after the response by design.
7. **00221 and the epics.** Question: archive 00221 now? Recommendation: yes, DONE with a note that T5-T7 live in epic 248 tickets; and decide 00300 (in or out of epic 253).
8. **00299 timing.** Security-critical and breaking for hand-written clients; the maintainer already approved (2026-11-08). Question: ship before 0.119.0? Recommendation: yes, it is the only security item in epic 251.
